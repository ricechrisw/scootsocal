## Design Specificity Verdict

**LLM assessment:** Not authored for Scoot SoCal. It is a category-interchangeable medical-scooter catalog that could take another Sun Belt dealer’s logo tomorrow.

The locked world is a hotel-curb operator: navy chrome on sand, Pride named in five seconds, Anaheim Resort + Hollywood/Universal delivery included in the number, three package ladders (day / 3-day / week) as the first-viewport object, Call equal to Request.

What shipped is a white product page. H1 is “Easy Scooter Rentals Delivered Right To You” (no Pride, no Anaheim, no Hollywood). The strip is “Starting at $X/day” toggles. The hero is a white-background manufacturer cutout (Go-Go JPEG with “Standard Color: Cardinal Red (matte)” in the pixels); `images/hero-curb.jpg` is unused. Header is a white bar with a clipart PNG lockup (palm, sun, waves, SOCAL in sky blue), not Scoot + citrus SoCal on navy. `--sand` compiles to `#ffffff`. There is no rates table. Coverage is an unmarked SoCal screenshot plus a same-day sentence that includes Downtown LA and Palm Springs.

It still looks like mobility (four wheels, Pride silhouettes, real phone number) rather than Lime or a Medicare mill. That is the category. It is not this operator.

HTML comments in `index.html` still describe the locked first viewport. The live page does not implement them. SEO title/meta still name Pride, Anaheim, and Hollywood; the visible H1 does not.

## Overall Impression

The page is a functioning lead-gen catalog with a real phone number and an honest “this is not checkout” form — then it spends the first five seconds on the wrong story. The single biggest opportunity is to put the actual offer back in the first viewport: Pride, hotel delivery included in Anaheim/Hollywood, three package prices, Call and Request dates, on the locked navy/sand/citrus chrome.

## What's Working

1. **Call is actually on stage.** Header, hero, How It Works, form lede, footer, and the mobile bar all expose `951-902-9375`. That matches a family operator, not a lead-gen trap — when the Request label is fully readable.
2. **The three machines are distinct and real.** Go-Go, Victory, and Maxima read as Light / Standard / Heavy-duty. Nobody will think Lime. The form sidecar that swaps the photo and a trip total after dates is the one piece that behaves like a rental shop.
3. **The form does not pretend to be checkout.** “This is a lead form, not live inventory. Or skip it and call” is the right sentence. FAQ on a dead scooter (“we’ll swap it”) is the right insurance. Footer correctly says rental only / not Medicare.

## Priority Issues

### [P0] First viewport abandoned the offer
- **What:** H1 is “Easy Scooter Rentals Delivered Right To You.” Price strip is only “Starting at $49/$59/$79/day.” Hero is a white cutout with manufacturer paint copy in the JPEG; `hero-curb.jpg` is unused. Tagline is “Show up. Scoot. We’ll handle the rest.” Delivery line never says Anaheim Resort or Hollywood/Universal, or that delivery is in the number.
- **Why it matters:** The visitor’s job is confirm medical scooter + hotel delivery included + see packages + call. In five seconds the page confirms none of that. “Starting at $49/day” hides the 3-day/week prices that are the competitive offer. SEO promises Pride + Anaheim; the H1 does not.
- **Fix:** Restore Pride + Anaheim and Hollywood hotels in the H1. Put day / 3-day / week for all three classes in the first viewport, citrus-bordered, stacked as rows on a narrow phone so Heavy-duty never clips. Caption: delivery included in Anaheim Resort and Hollywood/Universal. Pair Request dates + Call under it. Use the hotel-curb photograph.
- **Suggested command:** `/impeccable clarify` (copy + offer object) then `/impeccable layout`

### [P0] Phone layout clips meaning
- **What:** Captured phone-width screenshot: **Heavy Duty** clipped to “Hea.” Sticky bar shows **Request** cut off. CSS only stacks the price strip below 500px, so 500–799px still forces three columns. `body { overflow-x: hidden }` hides leftover overflow instead of fixing it. Trust row is `flex-wrap: nowrap`.
- **Why it matters:** The primary visitor is on a phone, often booking for a parent. If she cannot read the third class or the Request CTA, the page does not function.
- **Fix:** Stack the price strip on all phone widths; wrap every summary and step; give the sticky bar two full labels at equal width; remove the need for `overflow-x: hidden`.
- **Suggested command:** `/impeccable adapt`

### [P1] Chrome and palette are a different company
- **What:** `--sand: #ffffff`; `--paper: #ffffff`; sticky header is white, not `#0B1F3A`. Wordmark is a padded PNG (palm/sun/waves, SOCAL in blue, “DELIVERED. RELIABLE. READY.”) instead of Scoot + citrus SoCal. `theme-color` is `#ffffff`.
- **Why it matters:** The hotel-curb operator identity was navy field, sand ground, citrus for money and action. This reads as a generic DME Shopify theme with an Orange County tourism logo.
- **Fix:** Navy header, sand page, paper cards, citrus only on money/action. Crop or replace the lockup so SoCal is `#E85D04` and the logo does not arrive with white padding.
- **Suggested command:** `/impeccable colorize`

### [P1] Coverage and price truth are mushy
- **What:** Area line promises same-day to Disneyland, Universal, Downtown LA hotels, Hollywood, and Palm Springs. How It Works: “anywhere in our Southern California Delivery Zone.” FAQ: “provide your address at checkout”; “included … within our standard service area.” No extra-day column, no deposit/ID, no free vs quote. Map is an unmarked SoCal screenshot. Footer lists San Diego as if it were a core zone.
- **Why it matters:** Product truth: headline price includes delivery only in Anaheim Resort + Hollywood/Universal; SD and Palm Springs are quoted; no fake statewide; no invented checkout. Over-promising either creates a surprise invoice or a credibility hit.
- **Fix:** Two core zones (free, included in the number) vs two quote zones. Kill “checkout.” Publish the full grid (1 / 3 / 7 / extra day) and one line on tax + refundable deposit at delivery.
- **Suggested command:** `/impeccable clarify`

### [P2] Class is a catalog loop, not a match
- **What:** Strip buttons drive a carousel; fleet repeats the same three JPEGs with “Reserve now”; form `<select>` does not inherit the strip; optional rider weight, city, and notes are gone; CTA verbs rotate (Request dates / Reserve now / Request availability).
- **Why it matters:** Working memory tax. “Reserve now” on a mailto form is a trust tax. No weight means the adult child cannot match dad to Heavy-duty without calling — and typical capacity is never stated.
- **Fix:** One class chooser that sets the form. Fleet cards: analog line + typical capacity + package prices. One citrus verb: Request dates. Optional weight range framed as class matching.
- **Suggested command:** `/impeccable distill`

- Build card empty state says “Choose a scooter type” while Light Duty is already selected (JS fills it on load; empty copy still sits in markup).
- Price-strip buttons do not set `klass` on the form; Reserve now does not either.
- Fleet/hero JPEGs include manufacturer marketing lines as pixels; alt text cannot cancel that.
- “Call or text” adds a channel the rest of the page does not support.
